# 把项目交给 AI 协助构建

[简体中文](AI_BUILD_GUIDE.md) | [English](AI_BUILD_GUIDE.en.md)

本项目完整名称为 **FINAL FANTASY RESONANCE Native macOS（最终幻想：共鸣 macOS 实验适配）**，基于 nxnative。它提供现有移植方案的源码和构建入口，不需要让 AI 重新设计整套移植引擎。

## 一个链接能解决什么

AI 可以通过仓库了解支持版本、上游依赖、构建入口和已知问题，帮助检查环境、运行脚本与排错。成功构建仍需要用户自己的游戏输入、密钥，以及能在其 Apple Silicon Mac 上操作终端和文件的执行环境。没有本地执行能力的聊天助手只能给出步骤，用户需要自己执行。

**本机现有适配版本可运行，不等于这里新整理的入口已经在全新环境验证成功。** 请保留这个区别，不要将构建计划或静态检查通过描述为移植完成。

## 用户需要给 AI 的信息

| 信息 | 示例或要求 |
| --- | --- |
| 项目链接 | `https://github.com/Kisenshin/final-fantasy-resonance-native-macos` |
| Mac 型号与系统 | Apple Silicon 型号、内存容量、macOS 版本 |
| 本体路径 | 用户自己的港版本体 NSP；基础标题 ID `0100B8A026F14000` |
| 更新路径 | 用户自己的港版 1.0.1 更新 NSP；更新 ID `0100B8A026F14800` |
| 密钥路径 | 自己从主机导出的 `prod.keys` 的本机路径，无需发送密钥内容 |
| 私有工作目录 | 源码仓库之外，建议有约 100～120 GiB 空余空间 |
| 可选 DLC | 自有 DLC 路径和索引；已测试挂载的礼包索引为 `2` |

准备固定上游版本的源码需要联网；依赖安装和 .NET 包还原也可能需要网络。主程序和 shader 构建在本机完成。对其他地区或版本，本项目没有运行保证，脚本中的 build ID 检查会拒绝不匹配输入。

- 私有构建目录：[源码仓库之外的本机路径]

## AI 应遵循的构建顺序

1. 检查依赖并阅读验证状态；完整构建可能占用大量空间，不要把现有 shader 缓存可复用当作从零构建已经成功的证据。
2. 克隆本适配仓库，在仓库外运行 `scripts/prepare_runtime.py --destination ...` 准备固定版本的 nxnative。不要直接换成上游最新版本或另一个地区的配置。
3. 在正确的 Python 环境查看 `python scripts/build_mac.py` 的计划，再按 README 给出实际输入并执行 `--build`。
4. 日志位于用户的私有工作目录。输入检查、重写、shader 编译、FPS 菜单补丁和打包各自都有可能失败；以实际退出状态和输出检查为准。
5. 构建结束后检查签名、启动与实际游戏画面。标题可见、继续游戏可用、进入场景和存档读取是不同验证项，应分别记录。
6. 如果需要向项目报告问题，提供环境、build ID、具体错误及去除个人信息后的日志。不要上传密钥、游戏模块、资源或生成的完整应用。

直接命令、全部依赖和输入要求以 [README](../README.md) 为准。支持的游戏版本不会因为由 AI 执行而扩大，已知粒子问题和偶发卡顿也不会自动消失。
